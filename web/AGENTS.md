# SmartTest Web 临时开发手册

本文件仅约束 `web/**` 的长期 Web 开发阶段，是根目录 `AGENTS.md` 的 Web 局部补充。两者冲突时，除 Coco 对 Web 的明确指示外，仍以根目录规则为准。本文件不是全局开发规则；Web 长期开发完成并经 Coco 确认后移除。

产品与架构基线见 `web/WEB_DEVELOPMENT_DESIGN.md`。不要在任务报告中重复整份需求。

## 1. 开发方式

- 采用“单模块设计、单模块实现、单模块验收，最后整合”。
- 模块顺序默认遵循设计文档；Coco 可以调整顺序。
- 每次只修改当前已批准模块及其必需公共接口。
- 新模块开始前先调查已有 owner、接口、依赖、测试和真实运行环境。
- 模块执行清单写入 `web/WEB_DEVELOPMENT_DESIGN.md` 对应部分，不创建重复的实现计划文档。
- 未经 Coco 批准，不改变业务含义、数据权威、权限范围、读写边界或模块顺序所依赖的公共契约。

## 2. 强制复用

- 能复用仓库现有 owner、数据模型、服务、采集器、过滤器、调度器、认证、日志、配置、缓存或依赖时，必须直接复用。
- 不询问是否复用已有机制；复用是默认要求。
- 只有 Coco 主动要求独立封装，或现有能力经证据证明无法覆盖且 Coco 批准后，才新增平行机制。
- Web 不复制人员、项目、认证、Confluence 采集、Jira/Redmine 集成、审查、调度、测试运行或报告逻辑。
- 实现前报告复用 owner 和净新增生产代码；避免薄包装、无意义文件拆分和重复模型。

## 3. 依赖与所有权

依赖方向固定为：

```text
web/frontend -> web/backend -> core
```

- `web/frontend` 负责布局、交互和展示状态，只访问 Web API。
- `web/backend` 负责认证、权限、传输模型、请求编排和 Web 自有持久化。
- `core` 中的既有模块继续拥有项目发现、第三方访问、测试业务和其他核心行为。
- 浏览器不得直接访问 `core/`、Confluence、Jira、Redmine、数据库或本地配置文件。
- Web 后端不得把已有核心业务复制到 `web/`。
- Home 只聚合其他模块结果，不拥有独立指标计算或项目关系。

## 4. 数据权威

- Confluence 是项目主数据源。
- Jira、Redmine 是缺陷和任务辅助数据源。
- SmartTest 后续提供测试任务、执行和报告事实。
- `core/config/personnel.json` 是人员、职级、汇报关系、产品线分配和系统角色的唯一来源。
- 当前第三方数据保持只读；不得从 Web 修改 Confluence、Jira 或 Redmine。
- Web 自有数据库只保存快照、人工审查节点、历史指标和审计记录。
- Wi-Fi Database 保持独立只读 owner，不写入 Web 历史数据。
- 不生成模拟业务数据，不以缓存或旧数据冒充最新数据。

## 5. 权限

- 复用现有 SmartTest 认证，不建立 Web 本地账号体系。
- 后端将当前账号匹配到 `personnel.json`。
- I 岗只能读取本人、本人参与项目及被授权公共数据。
- M 岗可见范围为 `reports_to` 递归下属与本人负责产品线成员的并集。
- 后端统一执行页面、API、统计和导出的数据范围过滤。
- 不信任前端提供的账号、角色、产品线或管理范围。
- 未匹配人员、停用人员和越权请求不得默认放行。

## 6. 历史与审查

- 复用 `core/tools/common/project_weekly_audit/` 的项目发现、稳定身份、过滤、审查和调度能力。
- 定期自动采集形成连续项目快照。
- 管理岗人工审查形成不可覆盖的正式阶段节点。
- 历史记录必须包含来源、采集时间、业务周期和口径版本。
- 外部读取失败要保存或返回失败事实，不用旧数据补成成功结果。
- 历史修订形成新版本，不原地覆盖已经发生的事实。

## 7. 前端规则

- Web 唯一公共视觉体系为 Apple 风格，遵循 `docs/superpowers/specs/2026-10-18-web-apple-design-system.md`，包含外观、图标、动画及风格复合/切换；旧模板不再作为视觉基线。
- `smarttest-theme.css` 统一拥有公共控件外观；页面和组件不得复制或覆盖公共按钮、输入、卡片、分段控件等外观，只保留自身布局和业务状态绑定。
- 保留 China Operator、Smart Device、TV、Global Operator & STB、Wireless Connection 五个产品线专属风格，以及既有登录 PCB/globe 背景动画（不是第六产品线皮肤）；由产品线视觉与动画 owner 复用，不按页面另建特例，不改变公共控件结构、焦点和状态规则。
- 登录动画由 `src/login-background.js` / `src/login-motion.css` 及原生命周期统一拥有，主题 PNG、生产入口、预览与必要测试均须保留；不得因公共控件统一而删除。登录 card/form/button 仍遵循公共 Apple owner。详细边界见 Apple 规范第 4.1 节。
- 公共布局、导航、筛选、表格、状态、图表、空状态和错误状态保持一致。
- 页面必须处理加载、无数据、无权限、配置缺失、部分成功和失败。
- 列表数据量可能增长时使用服务端分页、筛选和排序。
- 不把业务分组、权限、指标口径或第三方关系放在前端计算。
- 不继续把长期模块集中堆入单个 `src/app.js`。

## 8. 后端规则

- 路由、服务、传输模型和持久化按业务模块组织。
- API 先认证和授权，再访问或聚合数据。
- API 明确返回数据来源、数据时间和部分失败状态。
- 第三方调用使用有界超时并保留可诊断日志。
- 写入 Web 自有数据时处理重复提交、幂等和并发边界。
- 不在日志、响应或前端暴露密码、Token、Cookie、连接串或内部堆栈。
- 数据库 schema 变更必须有受控迁移和回滚/恢复考虑。

## 9. 测试与验收

每个模块至少验证：

- 核心 owner 复用边界；
- API 契约及错误状态；
- I/M 岗数据范围和越权请求；
- 页面加载、空数据、失败、部分成功和无权限状态；
- 历史数据的不可覆盖性和口径可追溯性（适用时）；
- 与已交付模块的集成；
- 现有 Wi-Fi Database 无回归（涉及公共壳时）；
- 前端测试、lint、build；
- 后端聚焦测试；
- `git diff --check`。

测试只保留重要业务、权限、历史、公共契约和回归边界。交付前移除探索性测试、重复等价用例、源码文本/形状断言、模拟业务数据和临时诊断。

## 10. 交付报告

报告保持结果优先且简洁，包含：

- 当前模块和验收结论；
- 修改文件；
- 复用的既有 owner；
- 测试命令及退出码；
- 实际环境验证；
- 未通过标准或限制；
- 相关工作区状态；
- 若使用 Mason，记录其任务身份。

不要重复产品背景、整份设计、源代码或完整日志。只有 Coco 明确要求“提交”“合并”或“push”时，才执行根目录 `AGENTS.md` 定义的交付流程。
